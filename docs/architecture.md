# Persistence and trust boundaries

`DataProvider` has local and Supabase implementations, selected by validated public environment configuration and authenticated user. Product screens use the same interface. `Repository` exposes profile, scan lifecycle, event CRUD, duplicate checks, exports, usage, rewards, referrals, flags, subscription and calendar metadata operations. Server-only scan reservations implement usage increments; server-only milestone functions create ledger entries. The browser intentionally has no arbitrary credit-creation method.

Local data remains compatible with `zest-snap-local-v2`. Only compact extraction results are persisted, never original files/base64. Guest milestones are device-only and not resistant to storage clearing. Cloud balance is calculated from the append-only ledger; profile.reward_balance is a historical field, never trusted. Local progress imports to profile preferences without awarding spendable balance. Credit-to-scan conversion is disabled (`credits_per_bonus_scan=0`) until pricing is approved.

Stable scan IDs and event fingerprints make guest merges repeatable. Fingerprints use normalized title, ISO date, local time, timezone and location. Cloud has a unique `(user_id,fingerprint)` index. Scan and agenda deletion are separate; neither operates on external calendars. Conflict policy: existing cloud copies win guest import; edits target changed IDs only. Queued cloud operations retain their original before/after snapshots and retry idempotently. Offline device caches are account-scoped and cleared on explicit sign-out. Multiple devices editing the same event use last successful explicit update, not a collaborative conflict editor.

AI uploads are limited before JSON parsing and checked for canonical base64, allowed MIME, signature and decoded size. PDFs are parsed for encryption/page limits. Images are compressed before transport. Locale/timezone are validated. Output uses a structured schema, runtime checks, conservative ambiguity guidance and explicit review. No text extracted from a document can instruct tools or change system rules.

Cloud allowance reservations are serialized per user in PostgreSQL and counted before calling AI. A rapid repeat/content replay is rejected. Attempts consume allowance, including an upstream failure, to keep cost exposure bounded. Operational request records distinguish completion; document text is excluded from logs. Local mode has a bounded per-instance hourly limiter. For scale-out local-mode public traffic, configure the prepared Redis REST limiter or a platform WAF limit; memory alone is not a global spending cap. Provider project budget limits remain a separate owner control.

Cloud flags are checked server-side for scanning and rewards. Unknown/unavailable cloud flags fail closed. Referrals default off; code includes stable invites, anti-self referral, once-only recipient claims and qualification only after a server-recorded successful scan. Do not enable referral rewards without monitoring and an approved abuse policy. Direct Google/Outlook, billing and push delivery stay disabled.

ICS files use stable SHA-256 UIDs, CRLF, UTF-8 line folding and escaped text. Timed events convert IANA zones to UTC; ambiguous/nonexistent DST local times require correction. All-day end dates are inclusive in UI and exclusive in ICS. A missing end time produces a one-hour calendar duration, disclosed in Settings. This is an export convention, not an AI-inferred end time. Generating a file is never proof of import.

The service worker caches only public client shells, static assets and icons. It never caches API/POST/auth/admin/RSC responses. Shell navigation is network-first; offline uses the installed shell. Each build emits a new worker revision. A waiting worker activates only when the user chooses Update; a one-shot controller listener reloads once. Old release caches are removed on activation. Physical install/splash/camera/calendar import still require device QA.

Settings retention deletes scan history on app open (default 90 days); it is not a background server retention SLA. Account deletion removes Zest data and sessions, not external exports. Original-source uploads are disabled at both application and storage-policy level.
